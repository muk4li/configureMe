# Windows-Bootstrap

configureMe enthält zwei Windows-Installationspfade:

- Die bestehenden Windows-Profile verwenden weiterhin die festen WinGet-IDs aus dem Katalog.
- Das Profil `windows-server-2022-developer` erzeugt ein eigenständiges ZIP unter `bootstrap\windows-server-2022-developer`. Dieses ZIP läuft lokal mit Windows PowerShell 5.1 und benötigt weder WinGet noch den configureMe-Webserver. Das vollständige Zielsystem ist Windows Server 2022 x64 mit Desktop Experience.
- Die native Anwendung `windows\ConfigureMe.Setup` ist ein selbstständig publizierbares .NET 10 WinForms-Setup für dasselbe Zielsystem. Die Oberfläche benötigt keine vorinstallierte .NET-Runtime, Git oder WinGet; Windows PowerShell 5.1 führt die bereits vorhandenen Module aus. `config\catalog.json` ist die gemeinsame Paketdefinition für Portal und Windows-Setup.

Für den Quick Setup Ablauf, Status je Paket, Report-Formate, Quellen und Release-Hinweise siehe [Kurzanleitung Windows Server 2022](quickstart-windows-server-2022.md). Das ZIP kann reproduzierbar mit `scripts\New-WindowsServer2022QuickSetup.ps1` gebaut werden. GUI-Build, Runtime-Extraktion und tatsächliche Testgrenzen stehen in [Setup README](../windows/ConfigureMe.Setup/README.md) und [Setup SECURITY](../windows/ConfigureMe.Setup/SECURITY.md).

Automatische Herstellerinstallationen erfolgen erst nach einer sichtbaren Planübersicht und der Eingabe `YES`. Bereits installierte Programme werden nicht aktualisiert. Paketdefinitionen deklarieren MSI, EXE, MSIX, Windows Capability oder manuell explizit. MSI-/EXE-Dateityp und deklarierte Architektur, HTTPS/Redirect-Hosts, Authenticode-Herausgeber und verfügbare offizielle Hash-Metadaten werden vor der Ausführung geprüft. Das Serverprofil verwendet den signierten klassischen Python-3.14-x64-Vollinstaller ohne AppX. Nur die exakt gepinnte offizielle 7-Zip-25.01-x64-MSI darf bei passendem festem SHA-256 unsigniert sein; ungültige Signaturen bleiben gesperrt. Paketgebundene Bootstrap-Ausnahmen ersetzen niemals die Prüfung der installierten x64-Anwendung. MSI-Dateien laufen über `msiexec.exe`; systemweite Pakete und OpenSSH erfordern Administratorrechte, ohne automatische Elevation. Python wird über den offiziellen Installationsmanager und dessen dokumentierten Runtime-Befehl per-user eingerichtet. Git bleibt manuell, weil ein unterstützter Silent-Aufruf und eine dafür geprüfte Publisher-Identität in diesem Bootstrap nicht verifiziert wurden. Docker Desktop wird auf Server nicht installiert und nur lesend geprüft. Teams erhält einen Web-Fallback.

Das ZIP enthält ein Datei-Hash-Manifest mit Quell-Commit und Dirty-Tree-Status; ein SHA-256-Beileger ist kein Herkunftsnachweis. Der Workflow `Windows Quick Setup validation` legt den CLI-Bootstrap und das GUI-Paket als CI-Artefakte mit sieben Tagen Aufbewahrung ab, publiziert aber kein GitHub Release. Weder Release-Signierung noch ein interaktiver Windows Server 2022 GUI-/End-to-End-Installationslauf sind zugesichert. Tests führen keine Softwareinstallation aus.
